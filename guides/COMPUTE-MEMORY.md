# 浏览器组卡内存管理

多选目标仍然按顺序执行，支持同时勾选 Skip 和非 Skip。

AP 计分的技能顺序矩阵缓存最多保留 16 个键，替代原来的 512 个；缓存淘汰只导致重新计算，不改变计分、候选池或搜索范围。测试对比 18 组技能输入，并复算已淘汰输入，结果与原计分器一致。

计算组件在批次结束或失败时终止，批次内部的求解记忆缓存随批次清除；CP-SAT 子进程在单次求解完成后释放。原生组卡与 CP-SAT 不同时保留空闲子进程。Python 在批次结束执行垃圾回收。

IndexedDB 续算写入只保留当前写入和最新待写入快照，避免慢写入堆积整个 SQLite ArrayBuffer。

组件内存分配失败时，释放子进程并重试当前步骤一次。再次失败会提示内存不足，已完成目标仍返回并按原流程保存或导出。已完成的计算结果与卡库不会因释放组件而删除。

验证命令：

- `node tools/test_compute_workers.cjs`：注入分配失败，验证重试、释放和部分结果保留。
- `python -B browser/tests/check_score_cache_memory.py <临时输出目录>`：AP 缓存淘汰前后分数对照。

这些措施降低内存压力，不保证任意设备和任意大卡池都能完成一次全选计算。复杂 AP 目标仍可能耗时很长。
