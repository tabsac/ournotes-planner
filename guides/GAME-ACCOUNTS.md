# Our Notes planner：主页与多游戏账号

主页集中提供网页登录、注册、QQ 关联和游戏账号管理。组卡仍在网页中运行；点击侧边圆形菜单进入组卡、卡库、养成、账号包导入、B25、验证与数据、关于网页版。菜单图标展开时旋转 90°；支持 Escape 收起，手机上位于左下方。

## 使用方式

1. 登录网页账号；需要机器人读取结果时关联 QQ。
2. 在「账号包导入」上传并确认账号包。新 UID 新增游戏账号，相同 UID 更新已有账号。UID 按字符串保存，避免长整数精度丢失。
3. 在主页切换账号，或用 ↑ / ↓ 调整顺序。不同账号的卡库、B25、计算记录和续算缓存分别保存。计算期间不能切换、导入或删除账号。
4. 点击删除，确认框显示「删除账号的同时会删除相应数据」，选择红色「是」执行，选择「否」或 Escape 取消。

未登录时可以使用本机数据；登录后的游戏账号列表与顺序通过服务器保存。删除已登录账号需要联网成功，避免只删本机而云端仍保留。上传包时如网络暂时不可用，标记待同步，恢复联网后重新登记并同步。

这里管理的是上传的游戏数据，不会登录游戏或保存游戏登录凭据。删除网页中的游戏账号也不会注销游戏账号。

## 数据与迁移

- `browser/game-accounts.js` 管理列表、当前 UID、导入、排序和删除。
- `browser/profile-storage.js` 保留原有标签页并发修改保护，切换时选择独立存储键。
- `browser/cloud-api.js` 按网页登录账号与游戏 UID 保存云端关联指针，上传结果附带 `gameUid`。
- `browser/profile-cloud.js` 仅恢复当前 UID 的卡库；网络请求结束后再次核对登录与游戏账号，避免切换期间串号。
- IndexedDB 的活动记录、多目标组卡记录和续算缓存按相同身份分开保存。
- 服务器通过 `(owner, uid)` 唯一键保存账号，排序必须包含完整列表。删除在同一事务内清理该用户、该 UID 的卡库、成绩和计算结果，并留下删除标记，阻止其他旧页面自动重新上传；只有重新导入账号包才解除标记。
- 旧卡库有明确 UID 时迁移；旧本地数据没有可信归属证据时保留为访客数据。旧 UID 已经丢失精度时不猜测，保留卡库并提示重新取包。无法确定 UID 的历史计算结果不按猜测归属删除，可通过云端记录逐条管理。
- 删除清理当前数据；服务器例行备份仍遵循现有备份保留周期。

## 网页后端部署

纯静态镜像仍支持访客本机功能，登录与云端多账号需要网页 API。`server/game-accounts-api.patch` 是对现有 `tools/planner_api.py` 的网页接口补丁，未包含服务器配置或凭据；无需修改 ON bot 仓库。

新增接口（均使用原有网页登录鉴权）：

| 接口 | 作用 |
| --- | --- |
| `GET /api/game-accounts` | 列表及旧云端卡库迁移 |
| `POST /api/game-accounts` | 上传包导入时登记 UID |
| `PUT /api/game-accounts` | 保存完整 UID 顺序 |
| `DELETE /api/game-accounts/<uid>` | 删除账号及其可识别的对应结果 |

上线先备份 API 源码和数据库，再应用补丁、运行隔离测试、重启 API，等待探活成功，最后发布静态文件。静态资源先发布，`index.html` 最后替换，并完成双主机文件校验。回退源码不应自动覆盖已经发生用户操作的数据库。
