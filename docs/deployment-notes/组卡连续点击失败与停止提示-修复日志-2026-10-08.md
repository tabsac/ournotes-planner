# 组卡连续点击失败与停止提示 — 修复日志（2026-10-08）

用户最新要求：修复每次点击显示“本批已停止”；激奏保留现有文案与算法，仅去掉“实验性”。

## 已复现的原因

python-worker.js 第二次调用 deck-batch 时，用 sys.modules 判断模块已加载，却直接在 Python 全局上下文执行 deck_local.partial=None。模块只在 browser_runtime.invoke 函数内导入，某些首批计算没有触发 Native桥的全局import，因此第二次重置抛出 NameError: name 'deck_local' is not defined。

之前先跑Native引擎的测试碰巧触发桥中的全局import，未覆盖这个分支。本次以不存在歌曲的失败计算开头，连续重试成功复现了NameError。

另一个已确认的错误：deck-batch-ui.js 保存阶段把所有非complete状态都变成“本批已停止，已完成部分保存在本机”，覆盖真实失败原因；甚至没有结果时也声称已有结果保存。

## 修改

- 重置临时结果前显式 import deck_local。
- 每次调用明确设置/清空取消标志，不继承旧SharedArrayBuffer指针。
- 完成、取消、失败分别显示；失败保留具体错误原因。
- 没有完成任何目标时说明未生成结果，不写空的失败记录、不声称保存了部分结果。
- 仅在实际存在已完成sections时保存；本地或云端保存错误不会遮盖计算错误。
- 激奏标签只删除“实验性”，保留“参考”；已有记录与网页下载图片也移除该词。保留当前平均表现、薄弱场景数值及原排序，未改成“平均最高分”。
